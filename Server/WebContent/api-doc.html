Emporia Trading API

REST and WebSocket interface for trading applications

Overview

Emporia is a marketplace for trading commodities. A trading application talks to the server in two ways:

  • REST (JSON over HTTPS) for logging in, reading reference and market data, entering, modifying and deleting orders, and the bulletin board.
  • WebSocket for live updates: prices, market states, trades, and changes to your own orders and bulletins.

There are two kinds of markets:

  • Continuous and auction markets trade listed instruments through an order book. A continuous market matches orders as they arrive, in price-time priority. An auction market collects orders and matches them at scheduled times at one clearing price.
  • Bulletin markets hold informal, over-the-counter bulletins: a firm announces that it wants to buy or sell something, another firm makes an offer, and the bulletin's owner accepts or rejects it.

All paths in this document are relative to the server's base URL. For the server at hoddmimes.com this is https://hoddmimes.com/emporia, so the login is POST https://hoddmimes.com/emporia/api/login and the WebSocket is wss://hoddmimes.com/emporia/ws.

Conventions

Accounts are firms

Every user belongs to a firm. Orders, trades, bulletins and positions belong to the firm, not to the user: all users of a firm see and can modify or delete the firm's orders. A firm never sees other firms' orders, trades or identities; the public market data is anonymous.

A firm is authorized for certain markets by the marketplace administrator. Only those markets are listed, and a request for another market is refused with 403.

Prices and quantities are scaled integers

In the REST API every price and quantity is a long integer scaled by 100000: the price 101.50 is sent as 10150000 and the quantity 5 as 500000. This avoids rounding errors.

The WebSocket messages instead use ordinary decimal numbers (101.5, 5).

Each instrument has a tickSize and a lotSize, also scaled. An order's price must be a multiple of the tick size and its quantity a multiple of the lot size. With tick size 1000 (0.01) and lot size 100000 (1) the price 101.505 and the quantity 2.5 are refused.

Identifiers

  • marketId: an integer. Continuous, auction and bulletin markets share one numbering.
  • instrumentId: a long integer, the market id in the high 32 bits and a sequence number in the low 32 bits. Instrument 1 in market 1 is 4294967297.
  • orderId, bulletinId, tradeNo: hexadecimal strings, e.g. "6ace393800000001".
  • userRef (orders and bulletins) and offerRef (offers): optional free text that you choose. It is returned on everything that concerns the order, so you can match responses and messages to your own records.
  • clientAccount (orders): optional free text naming your firm's own account for the order, e.g. a client or a trader's book. An order without one is in the default account omni. It is carried on to the order's trades and your portfolio keeps a position per instrument and client account. It is private: never shown to other firms.

Times

Times (tradeTime, orderTime, expiresAt, createTime) are milliseconds since 1970-01-01 UTC. Dates in query parameters are yyyy-MM-dd.

Requests

Request bodies are JSON objects sent with Content-Type: application/json. All responses are JSON.

Trading status

Every market has a tradingStatus:

StatusContinuous / auction marketBulletin market
PREOPENOrders are accepted and put in the book, but nothing is matched. When the market opens, crossing orders are matched once at a single price.Not used.
OPENOrders are accepted and matched.Bulletins can be added, offered on and accepted.
CLOSEDNo new or modified orders, and no deletes.Only withdrawing a bulletin and rejecting an offer are possible.
SUSPENDEDNo new or modified orders; deleting is possible.As CLOSED.

An instrument can also be SUSPENDED on its own; its orders can then only be deleted. Markets open and close at their configured hours on weekdays. The MarketState WebSocket message tells you when the status changes.

Session and login

The API is session based. Log in once; the response sets an HTTP session cookie (JSESSIONID) that must be sent with every later request and with the WebSocket connection. Use a cookie store in your HTTP client. A session ends after a period without requests (5 minutes on the hoddmimes.com server); after that every request answers 401 and you must log in again.

POST/api/login

Logs in a trading user.

{ "firm": "ThinAir", "userId": "trader1", "password": "secret" }

200:

{ "success": true, "sessionId": "6A7A0F6E302A6A68F9F8B2C92F111A9A" }

401 for a wrong firm, user or password: { "success": false, "message": "..." }

POST/api/logout

Ends the login and closes the session's WebSocket connections. Always answers { "success": true }.

GET/api/session

Tells whether the session is logged in. Does not require a login.

{ "authenticated": true, "userId": "trader1", "firm": "ThinAir", "markets": [ ... ] }

401 with { "authenticated": false } when not logged in.

Errors

StatusMeaning
200, 201Success. 201 for a new order or bulletin.
400The request is invalid or was refused, e.g. a missing field, a price that is not a tick multiple, or a closed market. The body is { "error": "message" }.
401Not logged in, or the session timed out.
403The firm is not authorized for the market.
404Unknown market, instrument, order or bulletin. Another firm's order or bulletin is also reported as not found.

Example: { "error": "Market Equities is CLOSED, orders are only accepted when it is OPEN or PREOPEN" }

Every /api response carries an X-Request-Id header (r1, r2, ...). Quote it when reporting a problem; the server log shows it on every line about that request.

Markets

GET/api/markets

The continuous and auction markets the firm is authorized for. Bulletin markets are listed separately, see Bulletin markets.

{ "markets": [
  { "id": 1, "name": "Equities", "description": "Nordic equities", "type": "CONTINUOUS",
    "open": "09:00", "close": "17:30", "preOpenTime": "08:45", "tradingStatus": "OPEN", ... } ] }
FieldDescription
idThe marketId.
typeCONTINUOUS or AUCTION.
open, close, preOpenTimeTrading hours (server local time, weekdays).
tradingStatusSee Trading status.
auctionInterval, randomAuctionIntervalAuction markets: the time between auctions.

Instruments

GET/api/instruments?marketId=id

The market's instruments. marketId is required.

{ "instruments": [
  { "id": 4294967297, "marketId": 1, "name": "ABB", "instType": "EQUITY",
    "tickSize": 1000, "lotSize": 100000, "isin": "CH0012221716", "tradingStatus": "ACTIVE", ... } ] }
FieldDescription
idThe instrumentId, used in orders.
tickSize, lotSizeScaled. Prices must be multiples of tickSize, quantities of lotSize.
tradingStatusACTIVE or SUSPENDED.
instTypeCOMMODITY, EQUITY, OPTION, FUTURE or OTC; options and futures also have expirationDate, strikePrice, underlying, optionType.

Prices

GET/api/markets/{marketId}/prices

A price snapshot of every instrument in the market, sorted by name. Values are scaled; a value is null when there is none (an empty book side, or no trades today). For live prices use the PriceUpdate WebSocket message, which has the same fields in decimal form.

{ "marketId": 1, "prices": [
  { "marketId": 1, "marketName": "Equities", "instrumentId": 4294967297, "instrumentName": "ABB",
    "bidVol": 1500000, "bidPx": 9900000, "askVol": 100000, "askPx": 10000000,
    "open": 9950000, "high": 10100000, "last": 10000000, "volume": 4200000 } ] }
FieldDescription
bidPx, bidVolBest buy price and the total quantity at it.
askPx, askVolBest sell price and the total quantity at it.
open, high, lastToday's first, highest and latest trade price.
volumeToday's traded quantity.

Order book

GET/api/markets/{marketId}/orderbook/{instrumentId}

A snapshot of the instrument's whole order book, aggregated per price level, best price first. The book is anonymous, except that own tells how much of a level is your firm's.

{ "marketId": 1, "marketName": "Equities", "instrumentId": 4294967297, "instrumentName": "ABB",
  "bids": [ { "price": 9950000, "quantity": 200000,  "orders": 1, "own": 0 },
            { "price": 9900000, "quantity": 1500000, "orders": 2, "own": 1000000 } ],
  "asks": [ { "price": 10000000, "quantity": 100000, "orders": 1, "own": 0 } ],
  "open": null, "high": null, "last": null, "volume": 0, "time": 1791896537670 }

404 if the instrument is not in the market. The AddOrder, ModifyOrder and RemoveOrder WebSocket messages let you keep a book up to date after the snapshot.

Market trades

GET/api/markets/{marketId}/trades?instrumentId=

Today's trades in the market, oldest first, anonymous. Optionally for one instrument.

{ "marketId": 1, "trades": [
  { "marketId": 1, "marketName": "Equities", "instrumentId": 4294967297, "instrumentName": "ABB",
    "price": 10000000, "quantity": 200000, "tradeNo": "1", "tradeTime": 1791899978208 } ] }

Orders

Orders are limit orders with a price and a quantity, valid for the day. In a continuous market an incoming order first trades against the other side, at the resting orders' prices; whatever is not matched rests in the book. In an auction market orders rest until the next auction.

Orders are kept in memory only. They are gone after a server restart; trades are kept.
POST/api/orders

Enters an order. Requires the market to be OPEN or PREOPEN and the instrument not suspended.

FieldDescription
instrumentIdRequired.
sideRequired. BUY or SELL.
priceRequired. Scaled, > 0, a multiple of the tick size.
quantityRequired. Scaled, > 0, a multiple of the lot size.
userRef optionalYour reference.
clientAccount optionalYour firm's account for the order: 1–32 letters, digits, spaces or . _ - / (leading and trailing spaces are removed; left out or empty: omni; case-sensitive, so c1 and C1 are two accounts). Set once: it can't be changed by a modify. 400 if invalid.
{ "instrumentId": 4294967297, "side": "BUY", "price": 10000000, "quantity": 500000, "userRef": "b-17",
  "clientAccount": "client-7" }

201:

{ "orderId": "6ace393800000001", "inserted": true, "matched": 200000, "remaining": 300000, "userRef": "b-17" }
FieldDescription
orderIdThe order's id.
matchedThe quantity that traded at once. The trades themselves arrive as OwnTrade messages.
remainingThe quantity left in the book.
insertedtrue if a remainder rests in the book, false if the order traded completely.
PATCH/api/orders/{orderId}

Modifies one of your firm's resting orders.

FieldDescription
quantityRequired. The new remaining quantity.
price optionalThe new price; left out (or 0) keeps the current one.
userRef optionalA new reference; left out keeps the current one.

The order keeps its clientAccount, also when it is replaced; a request with a clientAccount field is rejected with 400.

The response has the same fields as for a new order. Lowering the quantity, or moving the price away from the other side, changes the order in place: it keeps its orderId and its original entry time for time priority. Raising the quantity, or moving the price towards the other side, replaces the order: it gets a new orderId (returned in the response), a new entry time, and may trade at once.

DELETE/api/orders/{orderId}

Deletes one of your firm's orders. Possible in every trading status except CLOSED.

{ "orderId": "6ace393800000002", "inserted": false, "matched": 0, "remaining": 300000 }

remaining is the quantity that was removed. 404 if the order no longer exists, for example because it has traded completely.

GET/api/orders?marketId=&instrumentId=

Your firm's resting orders, optionally for one market and/or one instrument.

{ "orders": [
  { "marketId": 1, "marketName": "Equities", "instrumentId": 4294967297, "instrumentName": "ABB",
    "orderId": "6ace393800000001", "side": "BUY", "price": 10000000, "quantity": 300000,
    "account": "ThinAir", "orderTime": 1791878914356, "userRef": "b-17", "clientAccount": "client-7" } ] }

quantity is the remaining quantity; account is your firm. userRef is missing if none was given.

Own trades

GET/api/trades?marketId=&instrumentId=&date=yyyy-MM-dd

Your firm's trades, oldest first: today's, or with date those of that day. Optionally for one market and/or instrument. 400 for an invalid date. The bulletin trades of the same day are listed apart, in bulletinTrades.

{ "date": "2026-10-12", "trades": [
  { "marketId": 1, "marketName": "Equities", "instrumentId": 4294967297, "instrumentName": "ABB",
    "side": "BUY", "price": 10000000, "quantity": 200000, "tradeNo": "1", "tradeTime": 1791899978208,
    "orderId": "6ace393800000001", "account": "ThinAir", "userRef": "b-17", "clientAccount": "client-7" } ],
  "bulletinTrades": [
  { "tradeNo": "6acf8b8700000001", "bulletinId": "6acf8b8700000001", "marketId": 2, "marketName": "OTC",
    "instrument": "Brent Jan", "side": "SELL", "price": 8000000, "quantity": 400000,
    "tradeTime": 1791986650009, "user": "ub", "ref": "o-3" } ] }

date is only in the response when it was given. If your firm traded with itself, the trade is listed twice, once per side. A bulletin trade has the bulletin's free text instrument and no instrumentId, so instrumentId leaves out all bulletin trades; user is the user of your firm that added the bulletin or made the offer, and ref that bulletin's userRef or that offer's offerRef (missing if none was given). A trade's clientAccount is that of your firm's order (omni for trades made before client accounts existed); bulletin trades have none.

Portfolio

GET/api/portfolio

Your firm's position per instrument and client account, from all its trades on every day: bought minus sold. Positions of 0 are left out. Sorted by market, instrument and client account.

{ "positions": [
  { "instrumentId": 4294967297, "instrument": "ABB", "marketId": 1, "market": "Equities",
    "clientAccount": "client-7", "position": 500000, "bought": 1500000, "sold": 1000000,
    "lastPrice": 10200000, "value": 51000000 } ],
  "totalValue": 51000000 }

lastPrice is the latest trade price (null if the instrument never traded); value = position × last price, negative for a short position.

clientAccount is the client account of your firm's orders in the trades (omni for trades made before client accounts existed, and for bulletin positions). Add the rows of an instrument up for your firm's total position in it. A trade between two of your own orders with different client accounts moves the position from one account to the other; your firm's total is unchanged.

Bulletin trades give positions of their own, per bulletin market and instrument text (the same text in two bulletin markets is two positions), with "bulletin": true and "instrumentId": null; their lastPrice is the latest bulletin trade price of that instrument text in that bulletin market.

Bulletin markets

GET/api/bulletin-markets

The bulletin markets your firm is authorized for. Note that the response is a JSON array.

[ { "id": 2, "name": "OTC-Machinery", "description": "Used machines", "tradingStatus": "OPEN",
    "open": "08:00", "close": "17:00", "instruments": [ "Old tractor", "/Brent.*/" ], "maxOrderTime": "168:00" } ]
FieldDescription
instrumentsWhat bulletins may be about. A plain entry must match the bulletin's instrument text exactly (case-sensitive); an entry between slashes is a regular expression that must match the whole text (/Brent.*/ allows "Brent Crude").
maxOrderTimehh:mm: how long a bulletin stays on the board before it expires. The hours may exceed 24.

Bulletins

A bulletin is an announcement in a bulletin market: a free-text instrument, and optionally a side, a price and a quantity. A bulletin without a side says that its owner will buy or sell: whoever makes an offer chooses. It is never matched automatically; other firms make offers on it. A bulletin stays until it is fully traded, withdrawn or expired.

StateMeaning
ACTIVEOpen for offers.
OFFER_PENDINGAn offer is waiting for the owner's answer. No other offer can be made, and the owner can't withdraw it.
TRADED, WITHDRAWN, EXPIRED, DELETEDRemoved from the board (DELETED: by the administrator).
POST/api/bulletins

Adds a bulletin. Requires the bulletin market to be OPEN.

FieldDescription
marketIdRequired. A bulletin market.
instrumentRequired. Free text, allowed by the market's instruments.
side optionalBUY or SELL; left out, null or empty means no side.
price, quantity optionalScaled; left out or 0 means not given.
userRef optionalYour reference.
{ "marketId": 2, "instrument": "Old tractor", "side": "SELL", "price": 100000000, "quantity": 500000, "userRef": "t1" }

201: { "bulletinId": "6acdec0800000001", "state": "ACTIVE", "expiresAt": 1792504800000, "userRef": "t1" }

GET/api/bulletins?marketId=

The bulletins in your bulletin markets (or one of them), oldest first.

{ "bulletins": [
  { "bulletinId": "6acdec0800000001", "marketId": 2, "instrument": "Old tractor", "side": "SELL",
    "price": 100000000, "quantity": 500000, "remainingQuantity": 500000, "state": "OFFER_PENDING",
    "createTime": 1791900000000, "expiresAt": 1792504800000, "own": true,
    "user": "trader1", "userRef": "t1",
    "offer": { "side": "BUY", "price": 95000000, "quantity": 200000, "expiresAt": 1791900060000, "own": false } } ] }

Everyone sees the public fields; a price or quantity of 0 means not given, a side of null that the bulletin has no side. The offer's side is the side of the firm that made it. own is true for your firm's bulletins, which also show user and userRef. A pending offer is shown to the bulletin's owner and to the firm that made it (with own: true and its offerRef).

DELETE/api/bulletins/{bulletinId}

Withdraws one of your firm's bulletins. Not possible while an offer is pending (answer it first). Possible in every trading status.

200: { "bulletinId": "...", "state": "WITHDRAWN", "remainingQuantity": 500000 }

Offers

POST/api/bulletins/{bulletinId}/offer

Makes an offer on another firm's bulletin. On a bulletin with a side the offer is on the opposite side; on a bulletin without a side you choose it. Requires the market to be OPEN, the bulletin to be ACTIVE and not your own.

FieldDescription
sideYour side, BUY or SELL. Required on a bulletin without a side. Optional on a bulletin with a side, where it must be the opposite of the bulletin's side.
priceRequired. Scaled, > 0.
quantityRequired. Scaled, > 0, at most the bulletin's remaining quantity (if it has a quantity).
validTime optionalSeconds the owner has to answer; default 60. Then the offer expires.
offerRef optionalYour reference.

200: { "bulletinId": "...", "state": "OFFER_PENDING", "remainingQuantity": 500000 }

The owner's firm is told by a BulletinOffer message; you get the answer the same way.

DELETE/api/bulletins/{bulletinId}/offer

Withdraws your firm's pending offer on a bulletin, before the owner answers it. Possible in every trading status. Both firms get a BulletinOffer with event CANCELLED, and the bulletin is ACTIVE again. 404 if your firm has no pending offer on the bulletin.

200: { "bulletinId": "...", "state": "ACTIVE", "remainingQuantity": 500000 }

POST/api/bulletins/{bulletinId}/response

Accepts or rejects the pending offer on one of your firm's bulletins: { "accept": true } or { "accept": false }.

Accepting makes a trade at the offer's price and quantity (requires the market to be OPEN). The remaining quantity drops; the bulletin is removed when nothing remains, or after its first trade if it had no quantity. Otherwise, and after a reject, it is ACTIVE again. Rejecting is always possible.

200: { "bulletinId": "...", "state": "TRADED", "remainingQuantity": 0 }

WebSocket

Connect to wss://<host>/<base>/ws (e.g. wss://hoddmimes.com/emporia/ws) after logging in, sending the session cookie with the connection request. There is nothing to subscribe to: the server sends every public message for the markets your firm is authorized for, and every private message for your firm.

  • On connect you first get a snapshot: the latest PriceUpdate of every instrument and the MarketState of every market. Bulletins are not in the snapshot; read them with GET /api/bulletins.
  • Send the text ping to get pong back. Send it right after connecting and wait for the pong: from then on the connection is registered and no message is missed. The server closes a connection that has been idle for 2 minutes, so send ping regularly (every 25 s is fine). The server also sends WebSocket ping frames, which most clients answer automatically.
  • Without a valid login the connection is refused or closed at once (code 1008, "Not authenticated"). Logging out or the session timing out closes it (code 1000).
  • Messages sent while you were disconnected are not repeated. After reconnecting you get a new snapshot; re-read your orders, trades and bulletins over REST.

Messages

Every message is a JSON object that starts with type, topic, marketId and, for instrument messages, instrumentId, followed by the type's own fields. Prices and quantities are decimals here, not scaled. A field that is null has no value (clear any previous value).

{ "type": "PriceUpdate", "topic": "/PriceUpdate/1/4294967297", "marketId": 1, "instrumentId": 4294967297,
  "bidVol": 15.0, "bidPx": 99.0, "askVol": 1.0, "askPx": 100.0,
  "open": 99.5, "high": 101.0, "last": 100.0, "volume": 42.0 }

Public messages

TypeWhenFields
PriceUpdateAfter every change to an instrument's book.bidVol, bidPx, askVol, askPx, open, high, last, volume; a complete snapshot each time.
MarketStateA market's trading status changes (also bulletin markets). marketName, tradingStatus
TradeA trade (anonymous).price, quantity, tradeNo, tradeTime
AddOrder
ModifyOrder
RemoveOrder		An order is added to, changed in, or removed from a book (anonymous).orderId, side, price, quantity (remaining), seqNo (per book, increasing). A partly filled resting order gives a ModifyOrder; a fully filled one a RemoveOrder with quantity 0. An incoming order that trades completely never enters the book and gives no order message.
BulletinA bulletin is added, changes or is removed (anonymous; a market message without instrumentId).event (ADDED, UPDATED, REMOVED), bulletinId, instrument, side (null when the bulletin has no side), price, quantity, remainingQuantity, state, expiresAt
BulletinTradeA bulletin offer was accepted (anonymous).bulletinId, instrument, price, quantity, tradeNo, tradeTime

Private messages (only to your firm)

TypeWhenFields
OwnOrderOne of your firm's orders is added, changed or removed.As AddOrder, plus event (ADDED, MODIFIED, REMOVED), userRef and clientAccount.
OwnTradeOne of your firm's orders traded (one message per side; both if you traded with yourself).side, price, quantity, tradeNo, tradeTime, orderId, userRef, clientAccount
OwnBulletinOne of your firm's bulletins changes.As Bulletin, plus user and userRef.
BulletinOfferAn offer on your bulletin (role OWNER), or your own offer (role OFFERER), changes.event (OFFERED, ACCEPTED, REJECTED, EXPIRED, CANCELLED: withdrawn by the offering firm, or the bulletin was deleted by the administrator), role, bulletinId, instrument, side (the offer's side), price, quantity, expiresAt (when the offer expires), and userRef (OWNER) or offerRef (OFFERER)

The counterparty of a trade or offer is never revealed. New message types or fields may be added; ignore what you don't recognize.

Example session

With curl, keeping the session cookie in a file:

BASE=https://hoddmimes.com/emporia
J='Content-Type: application/json'

# Log in
curl -c jar -b jar -H "$J" -X POST $BASE/api/login -d '{"firm":"ThinAir","userId":"trader1","password":"secret"}'

# Markets and instruments
curl -b jar $BASE/api/markets
curl -b jar "$BASE/api/instruments?marketId=1"

# Buy 5 ABB at 100.00 (scaled by 100000)
curl -b jar -H "$J" -X POST $BASE/api/orders \
     -d '{"instrumentId":4294967297,"side":"BUY","price":10000000,"quantity":500000,"userRef":"b-1"}'

# Lower it to 3, then delete it
curl -b jar -H "$J" -X PATCH $BASE/api/orders/6ace393800000001 -d '{"quantity":300000}'
curl -b jar -X DELETE $BASE/api/orders/6ace393800000001

curl -b jar -X POST $BASE/api/logout

The WebSocket in JavaScript (a browser sends the session cookie by itself):

const ws = new WebSocket('wss://hoddmimes.com/emporia/ws');
ws.onopen    = () => ws.send('ping');
ws.onmessage = (e) => {
    if (e.data === 'pong') return;
    const msg = JSON.parse(e.data);
    if (msg.type === 'PriceUpdate') console.log(msg.instrumentId, msg.bidPx, msg.askPx);
    if (msg.type === 'OwnTrade')    console.log('traded', msg.side, msg.quantity, '@', msg.price);
};
setInterval(() => ws.readyState === WebSocket.OPEN && ws.send('ping'), 25000);
