# Work
This document outline what is being worked on and at the same time shows a timeline of the work being done.

* 26-10-09 Established project and created a framework running the server. Add a claude init/principle document.
* 26-10-09 Created the Server app: Javalin web server, configuration, trading-user and admin login/authorization and the user database layer, ported from EmporiaX.
* 26-10-09 Added Server/WebContent with the trading client UI and the admin UI (under /admin) from EmporiaX; trading session now carries authorized markets.
* 26-10-09 Ported the complete EmporiaX admin functionality to the Server: firms, users, markets, instruments (incl. bulk load) and authorizations.
* 26-10-10 Added the trading endpoints /api/markets and /api/instruments, limited to the markets the user's firm is authorized for, so the trading market view loads markets and instruments.
* 26-10-10 Added InstrumentCache (from EmporiaX, without IPMC): markets and instruments are loaded at startup, kept in sync by the admin endpoints and used for trading reads, authorization checks and id allocation.
* 26-10-10 Deleting a market that still has instruments is now refused (409), so a reused marketId can't inherit orphaned instruments.
* 26-10-10 Added the /ws WebSocket for price updates (PriceFeed): session-authenticated, ping/pong, updates filtered by the firm's authorized markets. No price source exists yet.
* 26-10-10 Migrated the EmporiaX matching engine (continuous and auction books, auction scheduler) into the server's me package, with REST order entry (/api/orders, /api/trades), book changes published on the /ws price feed and the first unit tests.
* 26-10-10 Added the MarketStateScheduler: market states follow the market hours (PREOPEN/OPEN/CLOSED) on weekdays and stay CLOSED on weekends; OPEN markets are closed at startup, while -mode test opens all non-suspended markets and disables the scheduler. Also fixed admin edits wiping market and instrument names.
* 26-10-10 Added the TestClient subproject: a REST test program that runs concurrent trading sessions with AddOrder/DeleteOrder directives from a JSON file, repeated at a given txRate.
* 26-10-10 Fixed orders being rejected in OPEN markets: the engine required instruments to be ACTIVE, but instruments bulk loaded from EmporiaX files are stored as OPEN. Now only SUSPENDED instruments block orders, and the bulk load stores statuses other than SUSPENDED as ACTIVE.
* 26-10-10 Added the server util package with Timestamp, which collects nanoTime timestamps at labelled measuring points and reports the execution times between them.
* 26-10-10 Copied TXIDFactory from EmporiaX common into the server util package.
* 26-10-11 Orders can no longer be deleted while their market is CLOSED; deleting is allowed in OPEN, PREOPEN and SUSPENDED.
* 26-10-11 Fixed userRef on order modify: a PATCH without userRef keeps the order's userRef and one with userRef replaces it, both when the order is modified in place and when it is replaced; added modify tests.
* 26-10-11 Added the bdx package: the /ws WebSocket now broadcasts PriceUpdate, MarketState, anonymous Trade and AddOrder/ModifyOrder/RemoveOrder events to the firms authorized for the market, and private OwnOrder/OwnTrade messages to the owning firm (EmporiaX's topic scheme, without IPMC). BdxDistributor replaces PriceFeed; partial fills of resting orders are now reported as order modifications.
* 26-10-11 Added Database.saveTrade(InternalTrade), which stores a trade in the new Trades collection.
* 26-10-11 Added Database.listTradesByDate("yyyy-MM-dd"), which returns the stored trades of a day, latest first.
* 26-10-11 Added Database.listTradesByFirm(firm, "yyyy-MM-dd" or null for all dates), returning the trades where the firm is buyer or seller, latest first.
* 26-10-11 Added Database.deleteTradeByTradeNo(tradeNo), which deletes the stored trades with that trade number.
* 26-10-11 The matching engine stores each trade in the database (Database.saveTrade) and reloads today's trades at startup; the tc package (TradeCapture) was removed.
* 26-10-11 BdxDistributor sends asynchronously: publish() queues the message for the distributor's WsPublisher thread and the WebSocket sends are async, with a client more than 10000 messages behind disconnected; removed the per-WsContext send lock, which did not serialize sends.
* 26-10-11 Added Database.fromTradeDocument(Document), converting a stored trade back to an InternalTrade (new InternalTrade constructor taking the stored values, with stand-in buy/sell orders).
* 26-10-11 Added SessionUser (userId, firm), put on the Javalin context by a beforeMatched handler for matched non-admin /api requests; read with SessionUser.of(ctx).
* 26-10-12 Request ids: every /api request gets an id from a counter (r1, r2, ...), in the Log4j ThreadContext (shown as [%X{rid}] on each log line) and the X-Request-Id response header.
* 26-10-12 TestClient: -bdx true|false (default true) opens a WebSocket per session to /ws and prints every broadcast message received; no session sends transactions before all sessions are logged in and their WebSockets registered by the server.
* 26-10-12 Ported the bulletin board from EmporiaX (package bulletin, /api/bulletins endpoints); updates are pushed over /ws as bdx messages (Bulletin, OwnBulletin, BulletinOffer, BulletinTrade, OwnBulletinTrade).
* 26-10-12 REST: own orders and trades can be filtered by ?marketId=; new GET /api/markets/{marketId}/trades (public, anonymous trades) and GET /api/markets/{marketId}/prices (price snapshot per instrument).
* 26-10-12 Bulletin markets separated from the continuous/auction markets: own collection BulletinMarkets (name, description, OPEN/CLOSED driven by open/close times like the other markets, instruments as literal names or /regex/, maxOrderTime as hh:mm), admin pages and /api/admin/bulletin-markets; bulletins are stored in MongoDB, reloaded at startup and removed after the market's maxOrderTime.
* 26-10-12 Admin: Delete All Orders (market) and Delete All Bulletins (bulletin market), overruling authorization and market state; a market or bulletin market can only be deleted when it has no orders/bulletins.
* 26-10-12 Bulletin markets can be SUSPENDED (manual, never changed by the scheduler); only withdrawing bulletins and rejecting offers are allowed while suspended.
* 26-10-12 HTTPS is HTTP/1.1 only (SslPlugin http2 = false): browsers on https used WebSockets over HTTP/2 (RFC 8441), which Javalin doesn't handle, so /ws failed with 1006 in market-view.html.
* 26-10-12 Prices after a restart: today's reloaded trades restore open/high/last/volume and a PriceUpdate per instrument; market-view.html also loads GET /api/markets/{id}/prices when a market is selected.
* 26-10-12 market-view.html lists the authorized bulletin markets too; selecting one shows its bulletins, reloaded on each Bulletin message. Bulletin markets are listed below the other markets, under their own heading, in a teal color.
* 26-10-12 market-view.html Enter Order dialog: an order in a continuous/auction market or a bulletin in a bulletin market, validated for the selected market's kind before it is sent; MarketState messages keep the markets' trading status current.
* 26-10-12 market-view.html: a double click in the price table opens the order dialog for that instrument, on the bid as a BUY and on the ask as a SELL with that side's best price and volume.
* 26-10-12 market-view.html: clicking a bulletin opens an offer dialog (price, quantity, valid time in seconds, reference), prefilled from the bulletin.
* 26-10-12 market-view.html: a double click on the bid opens the order dialog as a SELL, on the ask as a BUY.
* 26-10-13 market-view.html: Bulletin Orders in the top menu shows the firm's own bulletins in all bulletin markets, with pending offers.
* 26-10-13 market-view.html: the Bulletin Orders view is split, own bulletins above and received offers (not expired) below; clicking an offer opens an accept/reject dialog.
* 26-10-13 market-view.html: a popup for each new offer received on the firm's bulletins (from the private BulletinOffer broadcast), with a countdown and an Answer button opening the response dialog.
* 26-10-13 market-view.html: desktop notifications (Notifications API) for new bulletin offers, in addition to the popup.
* 26-10-13 Portfolio: GET /api/portfolio (position per instrument from all the firm's stored trades, valued at the last traded price) and the My Portfolio view in market-view.html.
* 26-10-13 My Trades view in market-view.html: the firm's trades in all markets for today or a date entered as yyyy-MM-dd; GET /api/trades takes ?date= to read a day's trades from the database.
* 26-10-13 WebSockets survive background tabs: the server pings every 20 s (answered by the browser without JavaScript), idle timeout 2 min; market-view.html reconnects when the tab becomes visible and reloads the active view after a reconnect.
* 26-10-13 My Orders view in market-view.html: the firm's resting orders in all markets (or one market), reloaded on OwnOrder; a double click asks to delete the order. Orders in GET /api/orders carry orderTime.
* 26-10-13 Simulator module: a continuously running program that simulates market activity through the REST API (order flow with depth limits and matching orders for continuous instruments, bulletins created and withdrawn at random times) and prints its events.
* 26-10-13 Order book dialog in market-view.html: a click on an instrument shows a snapshot of its whole order book per price level (GET /api/markets/{marketId}/orderbook/{instrumentId}) with Cancel and Refresh; a click on a level opens the Enter Order dialog.
* 26-10-13 Packaging: a fat jar (Shadow) and a WAR for Tomcat 10.1+ (webapp.EmporiaWebApp starts the server, the REST API as a servlet, /ws as a Jakarta WebSocket endpoint; pages made relative so it runs at /emporia); build version and date generated at build time, GET /api/version, shown on the login pages. Deployed to hoddmimes at /emporia.

* 26-10-13 API documentation for trading application developers: Server/WebContent/api-doc.html (REST endpoints, scaling, errors, WebSocket messages, examples).
* 26-10-14 market-view.html layout: market dashboard (price table with separate bid/ask quantity and price columns and flashing changes, the firm's orders and today's trades in the market below), trading status badges in the market list, the active view's menu button highlighted, popups for accepted orders and own trades instead of messages in the order dialog.
* 26-10-14 Server startup (normal mode) also closes PREOPEN markets, not only OPEN ones, so a restart during market hours always comes up closed.
* 26-10-14 Bulletins without a side: the side of a bulletin is optional (BUY, SELL or none, EITHER in the web client); an offer on a bulletin without a side names its side, the owner trades the opposite. Server, web client (Enter Bulletin, offer and response dialogs), API documentation and Simulator (side NONE).

Tomcat gets the client address through a filter on /ws.
